# Master Project Execution Plan: Document Classification Service

**Project**: High-Stakes AI-Powered Document Classification System  
**Team Size**: 4 Engineers (API, Service/Repository, Infrastructure/ML, DevOps/Testing)  
**Architecture**: Strict Layered (API → Service → Repository → Infrastructure)  
**Tech Stack**: FastAPI, SQLAlchemy 2.0 (async), PostgreSQL, Redis + RQ, MinIO, HashiCorp Vault, Casbin (RBAC), PyTorch (ConvNeXt-Tiny)  
**Classification Scope**: 16 RVL-CDIP document classes with 0.7 confidence threshold for human review  
**Production Grade**: Zero-tolerance for abstraction leaks, atomic transactions, audit-complete

---

## 1. Executive Project Summary

### Strategic Mission
Build a **secure, auditable, and scalable document classification pipeline** that automatically processes scanned documents end-to-end: from SFTP ingestion through AI inference to role-based API access. The system must guarantee **data integrity**, **regulatory compliance**, and **operational observability** in a distributed microservices environment.

### Why This Is High-Stakes
- **Financial documents** (invoices, budgets) require **immutable audit trails** for compliance
- **Human resources materials** (resumes) demand **strict access controls** via RBAC
- **Scientific reports** necessitate **classification accuracy > 85%** to avoid misrouting
- The **0.7 confidence threshold** is a **business-critical rule**: any prediction below this MUST be flagged for manual review — a single missed requirement could result in legal exposure or financial loss
- **Secret leakage** (JWT keys, MinIO credentials) via Vault misconfiguration would compromise the entire security model

### Success Criteria (Non-Negotiable)
1. **Zero abstraction leakage**: SQLAlchemy ORM objects never escape repositories; HTTP exceptions never propagate to services
2. **Transaction atomicity**: Every write operation (user creation + audit, batch state change + prediction) commits or rolls back as a single unit
3. **Cache coherence**: `fastapi-cache2` Redis entries invalidated immediately on state change — no stale data served
4. **Audit completeness**: Every role change, relabel, and batch transition recorded with actor ID, timestamp, and JSON details
5. **Classification safety**: Low-confidence predictions (< 0.7) **must** be flagged; reviewers **must not** bypass this rule
6. **Model integrity**: ConvNeXt-Tiny weights verified via SHA-256 at startup; accuracy threshold enforced

### Risk Profile
| Risk Category | Impact | Mitigation Strategy |
|---------------|--------|---------------------|
| Secret exposure (Vault) | Critical | Read-only Vault token; secrets never logged; app halts on Vault failure |
| Cache staleness | High | Service-layer invalidation; cache-aside pattern; Redis transaction guards |
| Race condition (role change) | Critical | DB-level row locking; transaction isolation; last-admin check inside transaction |
| Worker data loss | High | RQ persistent queue; idempotent MinIO uploads; explicit batch state machine |
| Model drift | Medium | Golden test CI gate; SHA-256 verification; accuracy threshold |

### Phase 2: Core Implementation & Logic Integration (Week 3–5) — "Build the Engine"

**Parallel Workstreams**: All 4 engineers working concurrently on their layers with daily integration checkpoints.

#### Workstream A: Repository Layer (Hanan) — "Data Access Done Right"
**Files**: `app/repositories/user_repo.py`, `batch_repo.py`, `prediction_repo.py`, `audit_repo.py`

**Implementation Rules**:
1. Use `AsyncSession` from `app.db.session.AsyncSessionLocal`
2. Use `select()`, `update()`, `insert()` from SQLAlchemy 2.0 syntax
3. **Never call `session.commit()`** — service owns transaction
4. Convert ORM → domain via `DomainModel.model_validate(orm_obj)` (Pydantic v2)
5. Return `None` for not-found (do not raise `HTTPException`)
6. Use `returning()` on UPDATE statements to get fresh object without extra SELECT

**Critical Queries to Implement**:
- `UserRepo.count_by_role(role)` — single `SELECT COUNT(*)` for last-admin guard
- `PredictionRepo.get_recent(limit)` — `ORDER BY created_at DESC LIMIT`
- `BatchRepo.list_by_status(status, limit, offset)` — filtered list
- `AuditRepo.list_recent(limit)` — chronological audit feed

**Test Requirement**: Unit tests using `pytest-asyncio` with in-memory SQLite (`sqlite+aiosqlite:///:memory:`) — each repo method tested for CRUD + edge cases.

#### Workstream B: Service Layer (Lead) — "Business Logic Brain"
**Files**: `app/services/user_service.py`, `batch_service.py`, `prediction_service.py`, `audit_service.py` + `exceptions.py`

**Implementation Rules**:
1. `__init__(self, db: AsyncSession, cache: CacheInvalidator)` — dependencies injected
2. **Every write operation wrapped in `async with self.db.begin():`**
3. **Cache invalidation immediately after commit** (inside transaction block, before yield)
4. **Audit logging inside same transaction** — ensures audit trail never diverges from state change
5. Raise domain exceptions only: `PermissionDenied`, `NotFound`, `LastAdminError`, `RelabelNotAllowed`, `InvalidStateTransition`
6. **Never touch HTTP**: no `Request`, no `Response`, no `status_code`

**Atomicity Example** (user creation):
```python
async def create_user(self, data: UserCreate, actor: User) -> User:
    if actor.role != Role.admin:
        raise PermissionDenied("Only admins can create users")
    hashed = hash_password(data.password)
    to_persist = data.model_copy(update={"password": hashed})
    async with self.db.begin():
        user = await self.user_repo.create(to_persist)
        await self.audit_repo.create(
            actor_id=actor.id,
            action="user_create",
            target=f"user:{user.id}",
            details={"email": data.email, "role": data.role.value},
        )
    await self.cache.delete(USERS_LIST_KEY)
    await self.cache.delete(user_me_key(user.id))
    return user
```

#### Workstream C: Infrastructure Layer (Ashraf) — "External Integrations"
**Files**: `app/infra/vault.py`, `blob.py`, `cache.py`, `queue.py`, `sftp_watcher.py`

**Implementation Rules**:
1. **Vault**: Global `_client` singleton lazily initialized; `get_secret()` raises `RuntimeError` on failure; app lifespan hook catches and halts startup
2. **BlobStorage**: Uses `minio` Python SDK; thread-safe; `upload()` validates size (100MB cap); `exists()` for idempotency
3. **CacheInvalidator**: Protocol-first design; `RedisCacheInvalidator.from_client(app.state.redis)` (no new pool per request)
4. **ClassifyQueue**: RQ wrapper; `enqueue_classify()` passes kwargs to `app.workers.inference_worker.classify`
5. **SFTPWatcher**:
   - `run()` infinite loop with `try/except` around `_poll()` to prevent crash
   - `_list_new_files()` returns filenames not in `self._seen`
   - `_process_file()`:
     1. `blob.exists(blob_key)` → skip if already present (idempotent restart)
     2. `_sftp_download()` — size check before read
     3. `_reject_reason()` — zero-byte, extension, oversized → quarantine upload + return
     4. `blob.upload(original_key)`
     5. `queue.enqueue_classify()`
     6. `self._seen.add(filename)`

**Error Handling**:
- SFTP connection failure: log + return empty list → next poll retries
- MinIO upload failure: log + return (file NOT marked seen → retry next cycle)
- RQ enqueue failure: log + still mark seen (file in MinIO, ops can re-enqueue manually)

#### Workstream D: API Layer (Hussien) + Workers — "Interface & Execution"
**Files**: `app/api/main.py`, `routers/*.py`, `app/workers/sftp_ingest.py`, `app/workers/inference_worker.py`

**API Implementation Rules**:
1. **Lifespan hook order** (in `main.py`):
   ```python
   async def lifespan(app):
       verify_model_integrity()           # abort if model missing/weak
       jwt_secret = get_secret("JWT_SECRET")  # abort if Vault down
       assert Casbin policy CSV non-empty
       app.state.enforcer = await _init_casbin_enforcer()
       app.state.redis = redis.from_url(REDIS_URL)
       FastAPICache.init(RedisBackend(app.state.redis), prefix="")
       yield
       await app.state.redis.aclose()
   ```
2. **Router handlers**: 5 lines max. Delegate to service immediately.
   ```python
   @router.get("/me")
   async def get_me(user: User = Depends(current_domain_user), svc: UserService = Depends(get_user_service)):
       return await svc.get_me(user.id)
   ```
3. **Casbin guard**: Dependency function `_guard_*` or inline `enforcer.enforce(actor.role, resource, action)`
4. **Error translation**: `try/except` service exceptions → `HTTPException(status_code=403/404/400)`

**Worker Implementation Rules**:
- `sftp_ingest.py`:
  - `_create_batch()` callback: creates `BatchService` with fresh session + cache; closes cache after
  - `watcher.run()` — never exits; exceptions caught per-poll
- `inference_worker.py`:
  - `classify()` — RQ entry point; module-level import path `"app.workers.inference_worker.classify"`
  - Process-level singletons: `_blob`, `_model` initialized on first job
  - `_persist()` uses `asyncio.run(_persist_async())` to bridge sync→async
  - State transitions wrapped in `try/except InvalidStateTransition` (idempotent batch updates)

**ML Integration**:
- `app/classifier/model.py`:
  - `verify_model_integrity()`: checks `classifier.pt` exists, SHA-256 matches `model_card.json`, `test_top1 >= MIN_TOP1` (0.85)
  - `load_model()`: `convnext_tiny(weights=None)` → replace classifier head with 16 classes → load state_dict → `.eval()`
  - `predict()`: image → transform (Resize 256, CenterCrop 224, Normalize ImageNet) → forward pass → softmax → max class + confidence
- `app/classifier/overlay.py`: `draw_overlay()` → RGBA composite with 40px banner + 6px green confidence bar → PNG bytes

## 4. Critical Failure Point Analysis (Risk Mitigation)

### 4.1 Race Condition: Concurrent Role Updates
**Scenario**: Two admins simultaneously attempt to demote the last admin → both read count=1 → both allow demotion → zero admims remain.

**Mitigation**:
- **Serializable transaction isolation** (PostgreSQL default is Read Committed — insufficient)
- **Pessimistic locking**: `SELECT ... FOR UPDATE` on the `users` row when checking admin count
- **Implementation in `UserService.change_role()`**:
  ```python
  async with self.db.begin():
      # Lock all admin rows for this operation
      result = await self.db.execute(
          select(UserORM).where(UserORM.role == Role.admin).with_for_update()
      )
      admin_count = len(result.scalars().all())
      if admin_count == 1 and target.role == Role.admin and update.role != Role.admin:
          raise LastAdminError()
      # ... proceed
  ```

### 4.2 Cache-DB Inconsistency: Stale Batch List After State Change
**Scenario**: Batch A marked `done` by worker; cache still shows `pending` for 60s → auditor sees wrong status.

**Mitigation**:
- **Service-layer invalidation**: `BatchService.mark_done()` calls `await cache.delete(BATCHES_LIST_KEY)` immediately after `UPDATE`
- **Cache key design**: list key (`batches:list`) deleted; detail key (`batch:{id}`) also deleted
- **Write-through cache?** No — use **cache-aside** (lazy load on read, explicit delete on write)
- **Verification**: Test that after `mark_done()`, subsequent `GET /batches` misses cache and queries DB (check `cache.deleted` in tests)

### 4.3 Distributed Task Failure: RQ Worker Crashes Mid-Job
**Scenario**: Worker downloads from MinIO, runs inference, crashes before uploading overlay or writing prediction.

**Consequences**: Batch stuck in `processing`; prediction missing; overlay not stored.

**Mitigation**:
- **Idempotent job retry**: RQ moves failed job to `failed` queue; ops can retry via `rq retry`
- **No partial commit**: `PredictionService.save_prediction()` and `BatchService.mark_done()` happen in **same transaction**; either both succeed or neither
- **Overlay upload before DB write**: If overlay fails, job fails → retry → overlay will be re-uploaded (overwrite in MinIO OK due to same key)
- **Batch state machine**: `mark_processing()` may be called by multiple workers concurrently → `InvalidStateTransition` caught and logged (idempotent)
- **Monitoring**: Alert on jobs in `failed` queue > 0; alert on batches in `processing` state > 5 min

### 4.4 Abstraction Leak: SQLAlchemy ORM Exposed via API
**Scenario**: Repository returns ORM object; Pydantic serialization fails or leaks `hashed_password`.

**Mitigation**:
- **Repository contract**: "Always return domain model" enforced via code review and type hints
- **Type checker**: Mypy config to flag `UserORM` returned from repo functions
- **Test**: In `test_api_integration.py`, assert response JSON has no `hashed_password` field
- **Code pattern**: `return User.model_validate(user_orm)` — never `return user_orm`

### 4.5 Vault Unavailability at Startup
**Scenario**: Vault container slow to start → API container crashes → endless restart loop.

**Mitigation**:
- **Lifespan hook**: `get_secret("JWT_SECRET")` called before FastAPI starts serving — raises `RuntimeError` if Vault down
- **Docker Compose**: `depends_on` with `condition: service_healthy` on `vault-init` (which seeds secrets)
- **Healthcheck**: Vault has `vault status -address=http://localhost:8200` check
- **Retry limit**: Compose default restarts `on-failure` with backoff; team monitors logs

### 4.6 Model Drift: Corrupted or Incorrect Weights
**Scenario**: `classifier.pt` overwritten during training with low-accuracy model.

**Mitigation**:
- **SHA-256 verification**: `model_card.json` stores expected hash; `verify_model_integrity()` compares at startup → mismatch → worker refuses to start
- **Accuracy threshold**: `MIN_TOP1 = 0.85` in `model.py`; if `model_card["test_top1"] < 0.85`, startup fails
- **Golden test CI gate**: 50 golden images must match predictions exactly; any drift caught before merge
- **Git LFS**: Weights file versioned and tracked, preventing accidental overwrite

### 4.7 SFTP Drop Storm: Hundreds of Files at Once
**Scenario**: Vendor drops 500 TIFFs simultaneously → sftp-ingest overwhelmed → batch with 500 files → 500 RQ jobs flood worker.

**Mitigation**:
- **Batch grouping**: SFTP watcher groups files per poll cycle into a single batch — OK (batch_id shared)
- **Queue depth**: RQ persists jobs in Redis; workers can scale horizontally (multiple `worker` containers)
- **Rate limiting**: Not needed — ingestion rate limited by SFTP poll interval (5s)
- **Worker concurrency**: RQ default is 1 job/worker process; spawn multiple worker containers behind load balancer (not in current scope)

## 6. Senior Lead's Architectural Mandate (Golden Rules)

### Rule 1: The Service Layer Is the sole Transaction Boundary Owner
**Why**: If repositories commit, you cannot group multiple repo calls atomically.  
**Enforcement**: Code review red flag if `session.commit()` appears outside `services/`.  
**Correct pattern**:
```python
# services/user_service.py
async def create_user(...):
    async with self.db.begin():   # ← transaction opens
        user = await self.user_repo.create(...)   # no commit inside
        await self.audit_repo.create(...)         # same txn
    # ← transaction commits here automatically
    await self.cache.delete(...)   # after commit
```

### Rule 2: No Leaky Abstractions — Layers Communicate Only via Domain Models
**Why**: ORM objects carry DB session, lazy-loading, and internal state — leaking them couples layers.  
**Enforcement**: Type hints in repositories must return `User` (domain), not `UserORM`. Mypy strict mode catches violations.  
**Correct pattern**:
```python
# repositories/user_repo.py
from app.domain.user import User
from app.db.models import User as UserORM

async def get_by_id(self, user_id: str) -> User | None:
    result = await self.session.execute(select(UserORM).where(...))
    user_orm = result.scalar_one_or_none()
    return User.model_validate(user_orm) if user_orm else None  # ← conversion
```

### Rule 3: Cache Invalidation Must Be Idempotent & Immediate
**Why**: Deleting a non-existent key is safe; missing invalidation causes stale reads.  
**Enforcement**: Every public service method that mutates state **must** end with `await cache.delete(...)` (one or more keys). Test with `InMemoryCacheInvalidator` and assert `deleted` list contains expected keys.  
**Golden keys**:
- Single entity: `user:me:{id}`, `batch:{id}`
- List endpoints: `users:list`, `batches:list`, `predictions:recent`, `predictions:batch:{id}`

### Rule 4: The Confidence Threshold Rule Is Non-Negotiable
**Why**: Business requirement; reviewers cannot be trusted to decide (they may overrule AI on high-confidence correct predictions).  
**Implementation**: Hard check in `PredictionService.relabel()`:
```python
if actor.role == Role.reviewer and pred.confidence >= 0.7:
    raise RelabelNotAllowed("Reviewers may only relabel low-confidence predictions")
```
**Enforcement**: Unit test explicitly verifies `RelabelNotAllowed` raised for confidence 0.7+; code review to ensure no bypass.

### Rule 5: Audit Logs Are Write-Once, Read-Many
**Why**: Compliance requirement — tamper-evident trail.  
**Implementation**: `AuditLog` ORM has no `UPDATE` method in repository; only `create()` and `list_recent()`. Database schema has no `ON DELETE CASCADE` for `actor_id` (use `SET NULL`).  
**Verification**: Integration test checks audit entries exist for all 4 actions; attempt to modify audit row raises error.

### Rule 6: Secrets Never Touch the Filesystem or Logs
**Why**: Credential leakage = total compromise.  
**Implementation**:
- `vault.py`: `get_secret()` returns `str`; never `print()` or `log` the value
- Docker: secrets injected as env vars `VAULT_TOKEN` only; `JWT_SECRET` fetched from Vault
- `.env` file in repo root listed in `.gitignore` (if exists)
- Code scan: `grep -r "JWT_SECRET" app/ | grep -v "get_secret"` → must be zero

### Rule 7: Worker Idempotency Is Required
**Why**: Workers can crash/restart; jobs can be retried — no duplicate predictions or overlays.  
**Implementation**:
- `sftp_ingest`: `blob.exists(blob_key)` check before upload → skip if already in MinIO
- RQ job: `PredictionRepo.create()` uses `batch_id + filename` uniqueness? Not enforced — but duplicates OK (multiple predictions per file if job retried?). **Better**: `get_by_batch_and_filename()` check before create. **Decision**: Allow duplicates? Discuss with stakeholder. For now, assume idempotent by `blob_key` uniqueness constraint.
- Overlay upload: `put_object` overwrites same key safely

### Rule 8: Error Handling Stratification
**Layer** | **Exception Type** | **Example**
-- | -- | --
Repository | `ValueError`, `KeyError` | "User not found" → return `None`
Service | Domain exceptions (custom) | `PermissionDenied`, `NotFound`, `InvalidStateTransition`
API | `HTTPException` (FastAPI) | Translates service exceptions to 403/404/400
Worker | Unhandled → RQ moves job to `failed` | Log error, raise

**Never** mix layers: service does not raise `HTTPException`; API does not catch `ValueError` from repo.
